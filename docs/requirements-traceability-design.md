## 1. 문서 간 우선순위 (충돌 시)

```text
1. 사용자의 현재 명시적 결정
2. 승인된 변경 결정 (§2) — 영상 지시서/보충안에서 새로 승인된 3~4개 항목
3. 01 시스템 기준 명세의 제품 목표·F01~F17·P0/P1/P2
4. 실제 서비스 OpenAPI·Pydantic·권한·contract test
5. 06 통합 프롬프트의 디자인 분할 계약(UI_API_BOUNDARY_V2)
6. 영상의 정보구조·상호작용
7. 공개 디자인 시스템·사례
```

- 02는 "채택 판단" 자체가 01·06에 이미 흡수되어 있어 독립 규범력은 없고, **왜 B의 골격 + A의 상호작용을 채택했는지의 근거 문서**로만 참조한다.
- 03·04는 각각 "구현"과 "검증"의 실행 프롬프트이며, 06(디자인 담당)이 이번에 실행할 문서다. 03/04는 06이 소유하지 않는 API/백엔드 영역의 기준으로 남는다.
- 05는 **현재 검증된 산출물의 스냅샷**(commit `05fa1da9`, mock adapter, 배포 버전 4)이며, 06은 이 baseline을 회귀시키지 않아야 한다는 제약으로 인용한다.
- 영상 지시서·두 보충안은 01의 일부 조항(메타데이터 전용 MVP)과 정면 충돌하는 결정을 담고 있고, 이번 실행 범위에서는 **영상 계열 문서가 우선**하되 01 원문은 고치지 않고 `SPEC_ALIGNMENT_REQUIRED`로 남긴다.

## 5. 06 문서의 소유 경계 (다른 자료와의 역할 분리)

06은 8개 자료를 통합 실행하는 문서이지만, **UI/UX(디자인) 담당 범위만** 소유한다.

- **소유**: 앱 셸·시안·디자인 시스템·표현 컴포넌트·`UI_API_BOUNDARY_V2` props·상태별 화면(loading/empty/error/conflict 등)·폼·접근성·반응형·UI preview fixture·component/접근성/시각회귀 테스트
- **비소유** (03/04·05·백엔드 담당 영역): `mocks/backend/*.json`과 검증된 계약, 실제 API client·OpenAPI 생성 코드, network runtime schema/adapter, query key/cache/retry, 실제 업로드 전송·polling·SSE, 실제 인증·CSRF, 서버 인가·영속성·감사 판정, 시스템 명세 원문과 백엔드 문서

즉 06 실행 시 "구현 완료"로 보고할 수 있는 것은 **화면·상태·상호작용의 표현 계층**뿐이며, F04(파일 분석)·F05(근거 검증)·F07(체크 저장)·F08(알림)의 실제 서버 동작은 이번 산출물 범위 밖(`API_INTEGRATION_PENDING`)이다.

## 7. 8개 자료 간 중복·차이 요약

- **중복(설명 반복 불필요)**: OWASP Top 10 세부 설명, 접근성 WCAG 체크리스트 일반론, Source of Truth 결정 절차, 상태 코드 목록(`loading|empty|...|500`)은 01·03·04·06에 거의 동일하게 반복된다. 06 실행 시 이 부분은 01/03/04 원문을 인용하고 재설명하지 않는 것이 맞다.
- **차이가 실질적인 부분**: 03(구현)과 04(검증)는 각각 "쓰기 허용"과 "읽기 전용"이라는 상반된 실행 모드를 갖고 있어 **동시에 같은 세션의 지시문으로 적용하지 않는다**(04 §0 규칙 7, 03 실행문서 규칙과 동일 취지). 06은 03의 구현 허용 모드에 속하지만 소유 범위가 디자인으로 축소된 버전이다.
- **영상 계열 3종의 관계**: 지시서(원칙)→구현 보충안(03에 추가)/검증 보충안(04에 추가)로 역할이 분리되어 있고, 세 문서 모두 "이번 문서가 01 원문을 수정할 권한은 아니다"를 반복 명시한다.
